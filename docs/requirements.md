## 1. 背景與目標

### 1.1 背景

桌面操作系統自帶的防火牆以「入站防護」為主，對**出站連接**的控制要麼缺失（Linux 的 ufw/firewalld 不按應用控制），要麼缺少交互（Windows Defender 防火牆不會在應用聯網時詢問用戶）。現有的按應用聯網控制工具大多只支持單一平台：

| 平台 | 代表產品 |
|---|---|
| Windows | simplewall、Fort Firewall、Windows Firewall Control、GlassWire、NetLimiter、火絨聯網控制 |
| macOS | Little Snitch、LuLu、Radio Silence、TripMode |
| Linux | OpenSnitch、Portmaster |

跨平台且交互一致的產品很少（Portmaster 不支持 macOS）。

### 1.2 產品目標

1. 提供**跨 Windows / Linux / macOS** 的按應用聯網控制，三個平台的交互和規則模型保持一致。
2. 應用首次聯網時**彈窗詢問**，支持「允許 / 拒絕」×「本次 / 直到退出 / 限時 / 永久」等組合。
3. 讓用戶**看得見**：哪個應用、在什麼時候、連到了哪裡、用了多少流量。
4. 完全本地運行，**不收集任何遙測數據**。

### 1.3 非目標（本產品明確不做）

- 深度包檢測（DPI）、HTTPS 解密、內容過濾。
- 內置 VPN、代理或流量轉發。
- 企業級集中管控（MDM、多終端策略下發）。至少在 v1.x 不做。
- 防病毒或惡意程序查殺。
- **家長管控、兒童模式等對他人的強制管控**（2026-11-14 確定）。產品定位是幫用戶掌控自己的設備（隱私 + 自律）。作為普通應用無法防止繞過（例如在系統設定中斷開 VPN、強行停止或卸載、修改系統時間），做一半反而會給人「已經管住了」的錯覺。專注模式、時間表等「自己給自己設限」的功能不受此限制（見 FR-MOD-05 / 06）。

## 2. 術語

| 術語 | 說明 |
|---|---|
| 連接 / 流（Flow） | 一次網絡會話。TCP 指一條連接；UDP 指同一五元組在超時窗口內的報文集合 |
| 五元組 | 協議、本地地址、本地端口、遠端地址、遠端端口 |
| 判決（Verdict） | 對一個連接做出的決定：允許或拒絕 |
| 規則（Rule） | 持久化或臨時的判決條件集合，命中後產生判決 |
| 詢問（Prompt） | 沒有規則命中、且當前模式要求詢問時，彈出的用戶決策窗口 |
| 應用身份（AppIdentity） | 用來唯一標識一個應用的信息組合：路徑、簽名者、哈希、包 ID 等 |
| 引擎（Engine） | 各平台的底層攔截實現（WFP / Network Extension / NFQUEUE） |
| 核心服務（Core Service） | 以高權限運行的後台進程，負責規則匹配和判決 |
| 配置文件（Profile） | 一組規則和模式的集合，可以按網絡環境切換 |
| Fail-open / Fail-closed | 服務異常時默認放行 / 默認阻斷 |

## 3. 用戶與場景

### 3.1 目標用戶

| 角色 | 描述 | 核心訴求 |
|---|---|---|
| 隱私關注者 | 普通用戶，不希望軟件偷偷聯網上報數據 | 彈窗清晰、默認規則合理、不打擾 |
| 開發者 / 極客 | 熟悉網絡，想細粒度控制 | 按域名、端口規則，連接日誌，導入導出，CLI |
| 流量敏感用戶 | 用手機熱點或按流量計費的網絡 | 一鍵只允許少數應用，流量統計 |
| 家長 / 自律用戶 | 想限制某些應用在某些時段聯網 | 時間段規則，設置密碼保護 |

### 3.2 典型用戶故事

| 編號 | 用戶故事 |
|---|---|
| US-01 | 作為用戶，我安裝了一個新軟件，它第一次聯網時，我希望看到彈窗，告訴我是誰、要連去哪裡，讓我決定允許還是拒絕 |
| US-02 | 作為用戶，我不確定某個應用該不該聯網，希望能**只允許這一次**，或者**允許 15 分鐘**，之後再問我 |
| US-03 | 作為用戶，我希望某個應用**直到它退出前**都允許，下次啟動時再問 |
| US-04 | 作為開發者，我希望允許 VS Code 訪問 `*.github.com` 和 `marketplace.visualstudio.com`，其他域名一律拒絕 |
| US-05 | 作為熱點用戶，我希望切換到「熱點」配置文件後，只有微信和瀏覽器能聯網 |
| US-06 | 作為用戶，我想看到過去 24 小時哪個應用用了最多流量 |
| US-07 | 作為用戶，我想一鍵斷網（緊急情況），再一鍵恢復 |
| US-08 | 作為用戶，我不想被頻繁打擾，希望開啟「勿擾模式」，未知連接直接按默認策略處理，事後再在日誌裡審查 |
| US-09 | 作為用戶，某個應用更新後，我不希望它的規則失效需要重新授權；但如果程序被篡改，我希望收到警告 |
| US-10 | 作為用戶，我希望遊戲在工作日 22:00 到次日 07:00 之間自動不能聯網，幫我按時休息（2026-11-14 由家長場景改為自律場景，見 §1.3） |
| US-11 | 作為極客，我想把規則導出成文件，在另一台電腦上導入 |
| US-12 | 作為用戶，即使 UI 沒打開，攔截也應該持續生效 |

## 4. 平台支持範圍

| 平台 | 最低版本 | 架構 | 備註 |
|---|---|---|---|
| Windows | Windows 10 1809+、Windows 11 | x64、ARM64 | 階段 1 用用戶態 WFP，不需要驅動 |
| Linux | 內核 5.8+，nftables，systemd | x64、ARM64 | 參考發行版：Ubuntu 22.04+、Debian 12+、Fedora 39+ |
| macOS | macOS 13 Ventura+ | Apple Silicon、x64 | 需要 Network Extension 系統擴展，以及簽名和公證 |

各平台的能力差異（見 §6.1 FR-INT-07）必須在 UI 中如實展示，不能讓用戶誤以為所有平台的行為完全一樣。

## 6. 功能需求詳述

### 6.1 攔截與判決（FR-INT）

| 編號 | 需求 | 優先級 | 驗收標準 |
|---|---|---|---|
| FR-INT-01 | 攔截所有應用發起的**出站** TCP 連接和 UDP 流，覆蓋 IPv4 和 IPv6 | P0 | 用 curl 或瀏覽器訪問外網、`nslookup`、遊戲的 UDP 流量，都能在日誌中看到並受規則約束 |
| FR-INT-02 | 判決粒度為**連接級**：同一條已允許的 TCP 連接後續的報文不再逐包判決 | P0 | 一條已建立的連接在持續傳輸過程中，CPU 佔用沒有明顯上升 |
| FR-INT-03 | 本地回環（127.0.0.0/8、::1）默認放行，不彈窗 | P0 | 本地開發服務器訪問不觸發詢問 |
| FR-INT-04 | 內置系統必要流量放行：DHCP、DNS（由系統解析服務發出）、NTP、NetworkControl 自身 | P0 | 全新安裝後系統網絡能正常獲取 IP 和解析域名 |
| FR-INT-05 | ICMP 默認放行，可在設置中改為受規則控制 | P1 | 開關生效，`ping` 的行為隨之改變 |
| FR-INT-06 | **入站**連接控制：監聽端口收到外部連接時按規則判決或詢問 | P1 | 在 0.0.0.0 上啟動 HTTP 服務，外部機器訪問時觸發詢問 |
| FR-INT-07 | 引擎能力聲明：各平台引擎上報自己是否支持「掛起等待判決」等能力，UI 據此調整彈窗文案 | P0 | Windows 用戶態模式下，彈窗提示「此連接已被暫時阻止，允許後應用重試即可連接」 |
| FR-INT-08 | 待決連接**超時**：詢問等待超過配置時間（默認 30 秒）後，按默認動作判決 | P0 | 不回應彈窗，30 秒後連接按默認動作處理，日誌標記為「超時」 |
| FR-INT-09 | 按應用**限速**（上傳和下載分別設置） | P2 | 限速 1 MB/s 後，下載速度穩定在 1 MB/s 附近（±10%） |

### 6.2 應用識別（FR-APP）

| 編號 | 需求 | 優先級 | 驗收標準 |
|---|---|---|---|
| FR-APP-01 | 識別發起連接的進程：PID、可執行文件完整路徑、進程名、運行用戶 | P0 | 日誌中每條記錄都有以上字段，識別失敗時標記為「未知進程」並保留原始信息 |
| FR-APP-02 | 展示應用的友好名稱和圖標：Windows 讀版本信息，macOS 讀 bundle 名稱，Linux 讀 .desktop 文件 | P0 | 規則列表中常見應用顯示正確的名稱和圖標 |
| FR-APP-03 | 讀取代碼簽名信息：Windows 的 Authenticode 發布者，macOS 的 Team ID 和 Signing ID；Linux 可選讀取所屬軟件包 | P1 | Chrome 顯示發布者「Google LLC」 |
| FR-APP-04 | 應用身份匹配策略：**有簽名的按「簽名者 + 路徑」匹配，沒有簽名的按「路徑 + 哈希」匹配** | P1 | 已簽名應用升級後規則依然生效 |
| FR-APP-05 | **篡改檢測**：未簽名應用的哈希變化、或已簽名應用的簽名者變化時，暫停該應用的現有規則並發出告警詢問 | P1 | 替換一個已授權的未簽名 exe 後，下次聯網觸發「程序已變更」告警 |
| FR-APP-06 | 共享宿主進程細分：Windows 上 `svchost.exe` 按服務名展示；UWP/MSIX 應用按包名展示 | P1 | 規則列表能區分 `svchost (Dnscache)` 和 `svchost (wuauserv)` |
| FR-APP-07 | 解釋器類進程（python、node、java、powershell 等）支持按**命令行參數**細分規則 | P2 | 可以只允許 `python sync.py`，拒絕其他 python 腳本 |
| FR-APP-08 | 子進程歸屬：Chrome/Electron 等多進程應用歸併到主應用展示，可選「子進程繼承父應用規則」 | P2 | Chrome 的多個 helper 進程顯示在 Chrome 名下 |

### 6.3 詢問彈窗（FR-PRM）

#### 6.3.1 彈窗內容與交互

```
┌──────────────────────────────────────────────────────┐
│ [圖標]  Visual Studio Code                     (3)   │ ← 右上角：同應用待決數
│         發布者：Microsoft Corporation ✔ 已簽名         │
│         C:\Users\...\Code.exe                         │
├──────────────────────────────────────────────────────┤
│  想要連接到                                            │
│  marketplace.visualstudio.com  (13.107.42.18)        │
│  TCP 443 (HTTPS)  ·  出站  ·  美國 / AS8075 Microsoft │
├──────────────────────────────────────────────────────┤
│  範圍：(●) 此域名  ( ) 此應用的任意連接  ( ) 此 IP+端口 │
│  時效：[ 永久 ▼ ]  本次 / 直到退出 / 5分 / 15分 / 1時 /  │
│                    直到重啟 / 永久                     │
├──────────────────────────────────────────────────────┤
│  ⏱ 26 秒後自動拒絕           [ 拒絕 ]   [ 允許 ]       │
│  ▸ 更多詳情（PID、命令行、父進程、本地端口）              │
└──────────────────────────────────────────────────────┘
```

| 編號 | 需求 | 優先級 | 驗收標準 |

| FR-PRM-01 | 沒有規則命中、且當前模式為「詢問」時，彈出詢問窗口 | P0 | 新應用首次聯網時彈窗 |
| FR-PRM-02 | 彈窗展示：應用名稱、圖標、路徑、簽名狀態；目標的域名（如有）、IP、端口、協議、方向 | P0 | 字段齊全，信息缺失時顯示「未知」 |
| FR-PRM-03 | 動作：**允許 / 拒絕** | P0 | — |
| FR-PRM-04 | 時效：**本次、直到應用退出、5 分鐘、15 分鐘、1 小時、直到重啟、永久** | P0 | 各選項到期行為正確，見 FR-RUL-05 |
| FR-PRM-05 | 範圍：此應用的任意連接 / 此域名 / 此 IP / 此 IP+端口 / 此端口 | P1 | 選中的範圍生成對應條件的規則 |
| FR-PRM-06 | 倒計時和超時默認動作（默認拒絕，可設置為允許），倒計時可以暫停（鼠標懸停或展開詳情時暫停） | P0 | — |
| FR-PRM-07 | **防誤觸**：彈窗出現後 1 秒內不響應按鍵和點擊；默認焦點不放在「允許」上；不搶奪當前窗口的鍵盤焦點 | P0 | 打字過程中彈窗出現，不會因為按了回車而誤允許 |
| FR-PRM-08 | **合併**：同一應用的多個待決連接合併到一個彈窗，顯示計數，決策可以作用於全部或僅當前一個 | P1 | 瀏覽器同時發起 20 個連接只彈一個窗 |
| FR-PRM-09 | **排隊**：不同應用的詢問排隊依次顯示，最多同時顯示 1 個（可配置），並能看到隊列長度 | P1 | — |
| FR-PRM-10 | 記住上次選擇的「範圍」和「時效」作為下次的默認值 | P1 | — |
| FR-PRM-11 | 鍵盤快捷鍵：A 允許、D 拒絕、Esc 收起（按超時默認處理） | P1 | — |
| FR-PRM-12 | UI 沒有運行時（例如沒有用戶登錄），詢問直接按默認動作處理並記錄日誌 | P0 | 註銷用戶後，服務照常工作 |
| FR-PRM-13 | 多用戶：彈窗只出現在發起連接的用戶的會話中；系統帳戶發起的連接，詢問顯示給管理員用戶 | P1 | — |

### 6.4 規則（FR-RUL）

| 編號 | 需求 | 優先級 | 驗收標準 |
|---|---|---|---|
| FR-RUL-01 | 規則由「應用 + 條件 + 動作 + 時效」組成，應用可以是「任意應用」（全局規則） | P0 | — |
| FR-RUL-02 | 條件類型：遠端域名（精確、通配 `*.example.com`）、遠端 IP/CIDR、遠端端口或端口範圍、協議（TCP/UDP/ICMP/任意）、方向（出站/入站）、網絡類型（局域網/互聯網/本地回環） | P1 | 每種條件都有單元測試覆蓋 |
| FR-RUL-03 | 預設網絡範圍：「本地網絡」（RFC1918、鏈路本地、ULA、組播）、「互聯網」（以上以外的地址） | P1 | 可以一鍵設置「此應用僅允許局域網」 |
| FR-RUL-04 | **優先級**：條件更具體的規則優先；具體程度相同時「拒絕」優先；用戶也可以手動置頂（見設計文檔 §6） | P0 | 有一組規則衝突用例全部通過 |
| FR-RUL-05 | 時效實現：本次只作用於當前連接；直到退出在進程結束時失效；限時規則到點自動失效；直到重啟在服務重啟後失效；永久規則持久化 | P0 | 過期規則從生效列表移除，並在歷史中保留記錄 |
| FR-RUL-06 | 規則列表：按應用分組，支持搜索（應用名、域名、IP）、篩選（動作、時效、來源）、排序 | P0 | 1000 條規則時列表滾動流暢 |
| FR-RUL-07 | 規則增、刪、改、啟用/停用；批量操作 | P0 | — |
| FR-RUL-08 | 從日誌一鍵創建規則：在某條連接記錄上右鍵選「允許此類連接」或「拒絕此類連接」 | P1 | — |
| FR-RUL-09 | 規則來源標記：用戶創建 / 彈窗創建 / 系統內置 / 訂閱導入 | P1 | 內置規則不能刪除，只能停用 |
| FR-RUL-10 | 規則備註和最後命中時間，可以篩選「90 天未命中」的規則 | P1 | — |
| FR-RUL-11 | **時間段條件**：按星期和時段生效 | P2 | US-10 驗收通過 |
| FR-RUL-12 | **黑名單訂閱**：訂閱 hosts 格式或域名列表的 URL，定期更新，作為全局拒絕規則 | P2 | 訂閱公開的廣告/追蹤列表後，對應域名被拒絕 |

### 6.5 全局模式與配置文件（FR-MOD）

| 編號 | 需求 | 優先級 | 驗收標準 |

## 9. 平台能力差異與約束

| 能力 | Windows（用戶態 WFP） | Windows（驅動，後期） | Linux | macOS |
|---|---|---|---|---|
| 掛起連接等待用戶判決 | ✗ 先阻斷，允許後由應用重試 | ✓ | ✓ | ✓ |
| 「本次允許」的語義 | 臨時允許 60 秒（可配置） | 僅當前連接 | 僅當前連接 | 僅當前連接 |
| 進程 PID | 部分（阻斷事件中沒有 PID，靠連接表補全） | ✓ | ✓ | ✓ |
| 引擎直接提供域名 | ✗（靠 ETW DNS 事件） | ✗ | ✗（靠 DNS 嗅探） | 部分（`remoteHostname`） |
| 限速 | ✗ | ✓ | ✓（tc/nft 限速） | 有限 |
| 啟動保護 | ✓（持久化過濾器） | ✓ | ✓（早期加載 nft 規則） | 由系統擴展加載時機決定 |

**約束：**

- macOS 版需要 Apple Developer Program 帳號，以及 Network Extension 系統擴展的權限。
- Windows 驅動版需要 EV 代碼簽名證書和微軟簽名流程，所以排在後期。
- 參考 GPL 開源項目時只借鑒設計，不複製代碼（除非本項目決定採用 GPL）。

## 11. 風險

| 風險 | 影響 | 應對 |
|---|---|---|
| Windows 用戶態模式下「先阻斷後允許」體驗不如掛起模式 | 部分應用首次連接失敗後不重試 | 彈窗明確提示；後期提供驅動引擎；評估 WinDivert |
| macOS 權限申請週期和簽名成本 | M4 延期 | 提早申請；先用開發者模式（關閉 SIP）開發 |
| DNS 映射不準：DoH、共享 IP | 域名規則誤判 | 允許瀏覽器一類的應用按「任意連接」授權；在 UI 中提示域名僅供參考 |
| 彈窗打擾過多導致用戶卸載 | 留存率下降 | 首次引導時預授權、合併彈窗、勿擾模式、提供白名單模式 |
| 自身缺陷導致斷網 | 嚴重 | 默認 fail-open、看門狗、充分的混沌測試 |
| Avalonia 在 Linux Wayland 下的窗口置頂和托盤行為不一致 | Linux 體驗下降 | 按桌面環境逐一測試；托盤不可用時降級為通知加常駐窗口 |
