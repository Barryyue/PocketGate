01 — 核心机制

一次询问，三个决定

弹窗里没有层层选项，只有三个决定：动作、范围、时效。选完即生成一条规则，之后同类连接不再打扰你。

动作 Allow / Deny

允许或拒绝。默认焦点不落在「允许」上，弹窗出现后 1 秒内不响应点击与按键，打字时按到回车也不会误放行。

允许 · 拒绝

范围 Scope

决定这条规则管多宽。条件越具体的规则优先级越高；具体程度相同时，「拒绝」优先。

任意连接 / 域名 / IP / IP+端口 / 端口

时效 Lifetime

决定这条规则活多久。到期自动失效，从生效列表移除，但历史记录仍可回溯。

本次 / 直到退出 / 5 分钟 / 15 分钟 / 1 小时 / 直到重启 / 永久
▸
不打扰是设计目标。同一应用的多个待决连接合并成一个弹窗（浏览器同时发起 20 个连接只弹一次）， 不同应用排队依次显示，最多同时显示 1 个；等待超过设定时间（默认 30 秒）按默认动作判决并标记「超时」。 开启勿扰模式后不再弹窗，直接按默认策略处理，事后在日志里审查。
02 — 判决管线

从连接发起，到写入日志

判决路径不涉及 I/O 与阻塞调用。签名校验、哈希计算、日志写入全部异步，结果缓存。

01 拦截

引擎的过滤层看到每一条新的出站 TCP 连接与 UDP 流，覆盖 IPv4 与 IPv6。回环、DHCP、系统 DNS、NTP 与自身流量走内置放行。

WFPnftables + NFQUEUENetwork Extension

02 识别

PID → 完整路径 → 友好名称与图标 → 发布者或文件哈希。已签名应用按「签名者 + 路径」匹配，未签名按「路径 + 哈希」匹配，所以升级后规则不会失效；哈希变了则暂停规则并告警。

AuthenticodeTeam IDsha256

03 匹配

规则以不可变快照参与匹配，读路径无锁。条件更具体的优先，同具体程度时拒绝优先，也支持手动置顶。

p99 < 0.5 ms10⁴ 条规则 p99 < 2 ms

04 询问

没有规则命中、且当前模式为询问时进入 PromptBroker：按应用合并、跨应用排队、倒计时可暂停、UI 不在时按默认动作处理并记录。

< 300 ms 弹出30 s 超时

05 判决

结果写入判决缓存与活动数据库，同时记下依据：命中了哪条规则、哪个模式、还是超时。相同重复连接聚合计数，日志不会膨胀。

SQLite WAL依据可回溯

10 — 常见问题

先说清楚几件事

关于断网风险、域名准确性、平台差异和授权方式的直接回答。

它会不会把我自己的网弄断？
默认 fail-open：服务异常、崩溃或停止时放行流量。服务连续崩溃会自动降级为放行；也可以显式选择 fail-closed。 卸载时会清理过滤器、服务与系统扩展，不残留任何网络拦截。开机到服务启动之间的空窗期，各平台按自身能力尽量提供启动保护。
为什么域名有时不准？
拦截引擎本身不提供域名，靠 DNS 映射还原：Windows 用 ETW DNS 事件，Linux 用 DNS 嗅探，macOS 由系统扩展提供。 DoH、共享 IP 都会让映射失真。因此界面上的域名只作参考，可以展开看真实 IP；对浏览器这类连接密集的应用，建议直接按「此应用的任意连接」授权。
Windows 上「先阻断、再允许」是什么体验？
用户态 WFP 无法挂起连接等用户决定，所以首次连接会先被阻断，弹窗会明确提示「此连接已被暂时阻止，允许后应用重试即可连接」。 少数应用首次失败后不重试，这时可以在弹窗里直接授权或临时切到停用过滤。后期版本会提供驱动引擎，实现真正的挂起判决。
升级软件后，规则会失效吗？
不会。有签名的应用按「签名者 + 路径」匹配，没签名的按「路径 + 哈希」匹配。如果未签名应用的哈希变了，或者已签名应用的签名者变了， 会暂停该应用的现有规则并发出「程序已变更」告警，而不是悄悄沿用旧授权。
支持多用户和远程桌面吗？
询问弹窗只出现在发起连接的用户会话中；系统账户发起的连接，询问显示给管理员。没有用户登录时，询问按默认动作处理并写入日志， 服务照常工作。多用户场景是否进入 v1.0 范围仍在评审中。
开源吗？可以脚本化吗？
协议选型（MIT / Apache-2.0 / GPL-3.0）尚在评审，它决定能否参考或复用 GPL 项目的代码，所以暂时按「只借鉴设计、不复制代码」处理。 命令行工具 ncctl 提供状态查询、模式切换、规则增删查与导入导出，属于 P2 计划。
